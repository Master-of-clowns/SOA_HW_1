# Маркетплейс

Учебный API: товары, заказы, промокоды и пользователи. Python/FastAPI + PostgreSQL, схема БД создаётся через Flyway.

## Запуск

```sh
docker compose up --build -d --wait
curl http://localhost:8000/health
```

Ответ: `{"status":"ok"}`. Все методы можно вызвать через [Swagger](http://localhost:8000/docs).

Готовая демонстрация с настоящими запросами и SELECT:

```sh
docker compose exec api python demo.py
```

Она создаёт продавца и покупателя, товар за 100 рублей, промокод на 10%, заказ на две единицы за 180 рублей, затем отменяет заказ и показывает записи БД. Используются новые учебные аккаунты; пароли и токены не печатаются.

Остановка: `docker compose down`. Данные остаются в Docker volume.

Проверено после сокращения: Docker запускается, `/health` возвращает 200, демо и все 59 прежних тестов проходят. Сами тесты и старые отчёты из проекта убраны.

## Что происходит

1. **Docker Compose запускает PostgreSQL.** Это база с таблицами пользователей, товаров, заказов, позиций, промокодов и операций.
2. **Flyway применяет миграцию.** Он создаёт таблицы, индексы и триггеры дат, запоминает версию. При следующих запусках проверяет её, а не создаёт таблицы заново.
3. **На сборке генерируется код из OpenAPI.** В `openapi.json` описаны адреса API, поля и ограничения. `generate.py` создаёт модели данных и обработчики в `service/generated/`. Эту папку не нужно редактировать или добавлять в Git. Повторить генерацию: `python3 generate.py`.
4. **Запрос попадает в FastAPI.** Сначала проверяются входные поля, затем JWT и роль. После этого вызывается функция из `business.py`, выполняющая SQL.
5. **Результат возвращается как JSON.** Ошибки тоже имеют единый формат: `error_code`, `message`, при необходимости `details`. Каждый запрос записывается в JSON-лог; пароли и токены скрываются.

### Пример оформления заказа

Покупатель передаёт товары и количество. Сервер проверяет частоту запросов, отсутствие другого активного заказа, наличие и статус товаров, остатки и промокод. Затем уменьшает остатки и записывает заказ со снимком цены. Всё выполняется **в одной транзакции**: при ошибке изменения отменяются.

При обновлении заказа старые остатки возвращаются, новые резервируются, стоимость пересчитывается. При отмене резерв и использование промокода освобождаются. Строки БД блокируются на время операции, чтобы два покупателя не забрали последнюю единицу одновременно.

## Какие файлы читать

| Файл | Для чего |
|---|---|
| `openapi.json` | Контракт API: методы, DTO, ограничения, роли и ошибки |
| `generate.py` | Генерация моделей и обработчиков из контракта |
| `service/main.py` | Приём запросов, валидация, вызов логики, ответы и логи |
| `service/auth.py` | Регистрация, пароли, JWT и роли |
| `service/business.py` | Товары, заказы, промокоды и SQL-транзакции |
| `service/common.py` | Соединение с БД, ошибка API и обработка Decimal |
| `migrations/V1__marketplace.sql` | Схема БД для Flyway |
| `demo.py` | Один сценарий демонстрации |
| `Dockerfile`, `docker-compose.yml` | Сборка и запуск |
| `architecture.mmd` | C4-схема проектирования из первого задания |

В текущем задании работает один backend с общей БД: это позволяет атомарно изменить заказ и остатки. Схема первого задания описывает вариант с шестью сервисами; они здесь не запускаются.

## Методы и роли

- `/auth/register`, `/auth/login`, `/auth/refresh` — регистрация, вход и обновление токенов. Access действует 20 минут, refresh — 14 дней; refresh одноразовый.
- `/products` — CRUD товаров. Читают все роли; создаёт и меняет SELLER свои товары, ADMIN — любые. DELETE архивирует товар.
- `/orders` — создание, чтение, обновление и `/orders/{id}/cancel`. USER работает со своими заказами, ADMIN — с любыми. SELLER заказы не оформляет.
- `/orders/{id}/status` — ADMIN переводит заказ: CREATED → PAYMENT_PENDING → PAID → SHIPPED → COMPLETED. Отмена разрешена из CREATED и PAYMENT_PENDING отдельным методом.
- `/promo-codes` — создание промокода, SELLER и ADMIN.

В Swagger сначала зарегистрируйтесь, выполните login и вставьте access_token в **Authorize**. Для ADMIN сначала зарегистрируйте аккаунт, затем выполните `docker compose exec api python -m service.auth <username>` и войдите заново.

Параметры списка товаров: `page=0`, `size=20`, фильтры `status` и `category`. Минимальный интервал создания/обновления заказа задаётся `ORDER_RATE_MINUTES`, по умолчанию одна минута.

Деньги считаются через Decimal и NUMERIC(12,2). Изменение цены товара не меняет существующий заказ; явный PUT корзины берёт текущие цены. Процентная скидка свыше 70% даёт нулевую скидку согласно фразе задания «в ином случае цена 100%». При PUT неприменимый промокод снимается; собственное уже занятое использование не расходуется повторно.

Посмотреть БД: `docker compose exec db psql -U marketplace -d marketplace`. Например: `SELECT id, status, total_amount FROM orders;` или `SELECT id, stock FROM products;`.

Значения пароля БД и ключа JWT в Compose предназначены для локального задания. При необходимости задайте свои через переменные окружения или `.env`. Если порт 8000 занят: `API_PORT=8001 docker compose up --build -d --wait`.
